# 帝王评分卡：开发进度与待办

更新：2026-10-31。本文记录当前独立工作区的实现和检查结果；原始计划保留为历史设计与验收依据。

## 已实现

- 帝王工作台提供名录搜索、朝代筛选、拼音排序、桌面三栏和手机名录／评分／预览页面。未匹配当前名录的旧记录可在“其他本地存档”单独打开。
- 评分卡优先显示存档人物资料，包括多个在位区间、年号和庙谥；存档缺少相应资料时才回退到内置名录或占位文字。
- 两套算法使用独立草稿：固定十二维区分未评与零分，自定义等级轴显示评分、权重及扣分说明。支持分项理由、独立的一句话评价（最多 24 字符）、总体评价和可选署名；各算法的评价分别保存。
- 固定评分按钮和雷达图提供包含维度及分数状态的无障碍描述；卡片视觉上用横线表示未评分，同时提供供辅助技术读取的文字。
- 小屏固定评分面板限制高度并允许内部滚动，以便短视口下访问评分输入和关闭操作。
- 桌面和手机导航会将焦点移至目标区域，并标明当前导航位置；选择人物后转入评分区域。
- 帝王 Web 构建使用相对资源路径，可放在站点根目录或子目录；未改变音乐版 Toy／小工具的发布目标。
- 可选择仅占位图构建：不打包内置画像，用户仍可自行选择图片并随草稿保存；默认开发和普通构建仍使用原有画像。
- 自定义轴和扣分项在浏览器不提供 `crypto.randomUUID` 时使用本地唯一标识，并检查已有项目，避免添加操作因此中断。
- 浏览器本地自动保存、当前算法清空确认、JSON 备份与恢复已接入。其他页面修改同一草稿时会暂停本页自动保存并提供处理选择；保存异常时提供备份与重试入口，重试前再次检查本地数据是否变化。
- 导入备份前和用户确认后都会检查本地保存冲突；存在其他页面的修改时，先保留两边内容并要求处理冲突，再重新导入。
- 本地草稿无法解析时，暂停自动覆盖并提供“下载原始本地数据”；导出的文本保留读取到的原文，供人工排查，不保证损坏内容可以恢复。临时工作区的 JSON 备份是另一份数据。用户可在备份后明确确认，用临时工作区替换原始数据并恢复自动保存；替换前会再次检查本地数据是否变化。
- 本地存储读取受阻时，不假称已保留原始数据；允许重新检查。发现有效草稿需确认后载入，发现损坏数据可先导出原文，没有旧草稿时保存当前临时工作区。
- 评分卡提供原始长图和 11 种固定比例 PNG。横版使用独立布局，固定比例为保留完整内容而可能缩放留白；生成图可预览、下载，并在支持文件分享的浏览器中交给系统分享。内容变更后提供生成新图、取消和分享旧图。
- 原始长图使用 520 CSS 像素宽的独立渲染画布，优先 2 倍输出，避免手机窗口过窄导致导出图宽度过低；页脚与前面的评价内容保留间距。超长内容会降低渲染分辨率并提示用户。
- 对临时渲染画布设置像素面积和单边上限，以降低超长文本的内存压力。设备实际限制各不相同，此措施不能保证所有手机都能生成极长图片。
- 横版导出有多条分项理由时，会比较单栏与双栏的实际高度，双栏更紧凑才采用，以减少部分场景下的缩小；长文本仍可能需要使用原始长图。
- 带排名的视频封面未用于界面或新构建产物；相应人物暂用占位图。其他图片及人物资料的来源和使用权仍需核验。
- 可以为每个人物选择 JPEG、PNG 或 WebP 图片，压缩后随本地草稿和 JSON 备份保存，也可移除自选图片。浏览器存储空间有限，保存失败时应先导出备份。
- 导出时如果人物画像解码失败，本次生成使用占位图并提示用户，原画像和草稿不变；其他图片生成错误仍会提示失败。

## 已验证范围

- Chromium 中检查过 320、390、768、1024、1440px 的页面宽度；固定比例逐项检查过生成图片尺寸，并检查过长文本和双页面保存冲突。
- WebKit、Firefox 的代表性流程与限制见 [52 跨浏览器检查](./52_帝王工作台跨浏览器检查.md)。2026-10-31 两者复跑评分、画像、11 种比例和预览字节一致性、旧图分享选择、备份及冲突流程均通过；这些检查不覆盖所有新增失败恢复场景。axe 自动规则检查过桌面和手机名录／评分／预览，不等同于真实读屏验收。
- Chromium 独立会话模拟无法解析的本地草稿，验证导出的原始文本与本地数据一致、取消不覆盖、确认后临时内容可恢复；还模拟替换前本地数据发生变化，验证进入冲突处理且不直接覆盖。相关检查见 `scripts/emperor-recovery-check.js`。
- Chromium 检查过四条短理由的 16:9 双栏导出，验证条目完整且区域不重叠；再次通过 11 种比例的尺寸和预览字节一致性回归。其他长度和比例仍需视觉验收。
- Chromium 独立会话检查过无效 JSON 导入，以及模拟系统分享不支持、取消和失败：原评分和签名保留，页面给出对应提示；不支持时保留图片下载入口。检查脚本为 `scripts/emperor-failure-check.js`，模拟结果不代表真实手机或目标应用验收通过。
- Chromium 独立会话模拟浏览器存储空间不足，验证失败后可导出当前编辑、恢复后可重试保存并刷新恢复，且重试时不会直接覆盖已变化的本地数据；检查脚本为 `scripts/emperor-storage-failure-check.js`。
- Chromium 两页面检查过发生保存冲突时导入旧备份：导入被阻止，本页编辑和另一页面已保存的内容均保留；正常导入亦通过回归。检查脚本为 `scripts/emperor-import-conflict-check.js`。
- Chromium 模拟导出快照中的画像解码失败，验证 4:5 PNG 使用占位图、提示可见且原画像未改变；正常画像和 11 种比例也通过回归。检查脚本为 `scripts/emperor-portrait-failure-check.js`。

## 待完成

推进原则：双算法、保存恢复、图片导出和分享主流程已具备。后续优先处理实际反馈及发布所需素材，不逐项扩展边缘测试；修改后仅验证评分正确性、数据保存或图片导出等受影响的关键路径。

1. 为缺图人物整理不含排名文字、来源清楚且可用于发布的画像；逐项核对人物身份、年代和图片来源。当前资料不能以自动生成的馆藏说明视为核验结论。
2. 按实际反馈继续改善长理由及横版文字偏小的问题；优先查看原始长图、4:5、16:9 的代表性内容，其他比例发现问题时再针对性复查。
3. 测试真实手机上的键盘、安全区、图片下载和系统分享；分别核对取消、失败和不支持时的提示。当前分享测试包含模拟接口，不能据此声称目标平台接收或发布成功。
4. 根据选定发布目标完成必要的设备及无障碍确认，记录实际限制；发布前确定帝王版版本身份和素材状态。

## 运行与数据

在仓库目录运行 `npm install` 后执行 `npm run dev`，按终端显示的本地地址打开。运行 `npm run typecheck`、`npm test`，以及 `node --experimental-strip-types --test scripts/emperor-algorithm.test.mjs scripts/emperor-workspace.test.mjs scripts/emperor-roster.test.mjs` 可复验主要逻辑。

Windows 下可在一个终端运行 `npm run dev -- --host 127.0.0.1 --port 4231`，再在另一个终端运行 `npm run test:emperor-ui`。该检查使用独立浏览器会话，验证双算法评分与理由恢复、自选图片、十二维和长理由，以及 11 种比例的 PNG 尺寸和预览字节一致性、旧图分享选择、JSON 备份恢复和多页面保存冲突；它不替代图片视觉检查、真实手机或系统分享验收。

默认使用 Chromium；可分别通过 `npm run test:emperor-ui -- -Browser firefox` 和 `npm run test:emperor-ui -- -Browser webkit` 检查 Firefox、WebKit。需要预先安装相应的 Playwright 浏览器；本地地址不同时可追加 `-Url http://127.0.0.1:端口/`。三种浏览器的上述自动检查均已通过。

运行 `npm run emperor:build:placeholder` 可自动检查类型、创建新的独立目录、构建不含内置画像的测试版本并检查产物；命令输出实际目录。也可在 PowerShell 中设置 `$env:XDRATE_EMPEROR_PLACEHOLDER_ONLY = '1'`，手动执行 `npx vite build --outDir output/新的空目录 --emptyOutDir false`。手动构建后执行 `Remove-Item Env:XDRATE_EMPEROR_PLACEHOLDER_ONLY`，恢复普通构建；每次使用新空目录，避免混入旧产物。

构建后运行 `npm run emperor:audit:placeholder -- output/新的空目录`，检查通过后仍需完成界面、内容和目标平台验收。

帝王工作区保存在当前浏览器的本地存储中；清理浏览器数据可能删除草稿。JSON 备份最大为 16 MB，浏览器可用存储容量可能更小。清理前应导出备份并妥善保存。
