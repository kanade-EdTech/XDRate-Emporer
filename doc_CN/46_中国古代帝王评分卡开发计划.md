# 中国古代帝王评分卡开发计划

日期：2026-10-30。本文保留初版规划和验收标准；实施进度及剩余事项以[帝王版开发进度与待办](./53_帝王版开发进度与待办.md)为准。采用 Alex 的依赖分层、原子任务与可验收完成定义。

## 1. 需求与范围

### 用户已确定

1. 当前 `XDRate-Emporer` 转为古代帝王评分卡，第一阶段聚焦中国古代帝王。
2. 提供“自定义等级轴”与“十二维固定权重”两种算法；固定公式和逐项权重见 [45 双算法规范](./45_帝王评分双算法规范.md)。
3. 重构界面：宽屏参考 [`emperor-card-ui.html`](../design/emperor-card-ui.html)，竖屏参考 [`emperor-card-mobile.html`](../design/emperor-card-mobile.html)。
4. 本轮交付算法 Markdown、开发计划和执行提示词；不是已经授权实施全部里程碑。

### 建议实施默认值，后续可确认或修订

- 默认选十二维固定算法；每维 0–100、最多一位小数，滑块步长 1；区分真实零分与未评。
- 固定算法十二项齐全才显示正式总分；缺项显示完成度及权重覆盖率，允许明确标记未完成的草稿卡。
- 不预填分数、排名、好坏评价或自动评级。默认人物资料与“内容评分模板”是不同概念。
- A、B 各存一份草稿，切换不自动换算或覆盖；比较功能后置。
- 首发先做 Web 本地可用与 PNG／JSON 闭环，再验证容器；Toy、MiniTool、原生 App 和微信能力均不能由界面按钮反推为已实现。
- 产品显示名用 `XDRate Emperor`；仓库目录的 `Emporer` 拼写不自动改名。独立包版本、包名、Toy 名称／slug／ID 另行确认，不沿用音乐版条目。

## 2. 当前基线与必须纠正的误区

| 核查项 | 本目录现状 | 迁移要求 |
| --- | --- | --- |
| 算法 | `src/domain/rating/calculateRating.ts` 为 v4 固定扣分、普通轴 1–10 | A 保留数值行为；B 另建纯函数，不冒称已有 v5／五心。 |
| 数据格式 | `MusicRatingDraft`；`xdrate-music-archive/template`，schema v2 | 新帝王领域和双算法判别，不靠全局替换名字。 |
| 旧档迁移 | 会把正小数评分取整，0 代表未评 | B 不能经过旧迁移函数；旧音乐档默认明确拒绝，不静默转帝王。 |
| 草稿缓存 | `xdrate.music.*` | 新建 `xdrate.emperor.*`；不读写、清空音乐键。 |
| 入口 | Web 为 music/game；Toy 用路径猜是否游戏 | 显式帝王入口，不再由旧 URL 猜领域。 |
| 模板 | Web 结构模板不保存评分和内容；MiniTool 内容模板是另一套 | 分离人物资料、规则模板、我的评价，不能假设现成支持带分数人物模板。 |
| 卡片 | 11 比例、html-to-image、2× 输出；部分布局最多展示 6 项 | 重验十二维完整展示，不能沿用“截掉后六项”的容量假设。 |
| 页脚算法 | `CardFooter.tsx` 读取全局音乐算法版本 | 改由当前评分结果和存档版本提供真实标识。 |
| 设计素材 | `dist/皇帝` 共 265 个文件，69,651,929 字节；部分名字含来源排名 | 构建前先保全、清点、映射和来源核验；不把文件名前缀当排名。 |
| 设计脚本 | 两页均为已评分普通均分；缺值雷达补零；多处按钮未接线 | 只继承视觉与交互意图，算法／持久化／导出全部按正式契约实现。 |

当前目录的 `package.json` 仍是 `xdrate-music@0.4.1`。没有音乐新分支的 `preset:check`、`canva:check`，也没有本轮已经通过“287／54 项测试”的事实。测试数量必须在本目录实际运行后重记。

## 3. 视觉与交互规格

### 3.1 宽屏／横向工作台

参考桌面稿的“左名录—中卡片—右编辑器”三栏，沿用宣纸米白、浓墨、朱砂、沉金、印章和人物画像。1120px 左右的三栏只是布局建议；实际断点按内容宽度测试确定，平板不能硬塞三栏。

- 名录按朝代筛选，搜索姓名、本名、庙号、谥号、年号及别名；没有资料时不编造。显示“未评／已评 n/12／已完成”等状态，不显示来源排行榜。
- 同名、同庙号不能作唯一键；人物稳定 ID 驱动整条元数据及对应草稿切换。换人要保留或保护原评分，不只更换头像与姓名。
- 编辑器顶部清晰区分两种算法。固定算法展示不可编辑百分比；A 展示 LV 权重。编辑模式不新增成第三种算法。
- 中间卡片优先保证姓名、朝代、在位信息、算法名、总分／未完成状态、十二维数值和评分者签名可读。
- 采用十二轴雷达加四组条形／数值表作为互补；缺评不能画成真实零分，数据变化不依靠颜色单独表达。

### 3.2 竖屏／手机

移动稿是三部手机并列的展示板，不是要在产品中排出三部手机。提取其名录、评分、生成分享三屏信息架构，不复制假状态栏、刘海、390×800 固定机身或无法滚动的高度。

- 名录为画像卡片和横向朝代筛选；评分页上方是人物摘要及雷达，下方是分组维度格；点维度打开底部评分抽屉。
- 抽屉支持滑块、数值输入、±、清除此项和维度理由；首次拖动或明确确认才写入真实评分。未评状态下点 ± 不得隐式从 50 开始变 49／51，具体起始值提示后再确认。
- 底栏与抽屉处理安全区、软键盘、短视口和横竖切换。弹层有名字、关闭按钮、焦点管理和 Escape；主触控目标至少 44×44px。
- 所有平台均保证 PNG 可生成并有可用的本地保存／下载路径；系统相册和系统分享仅在平台实有能力时启用，否则提供下载图片与操作说明。不能声称浏览器下载就是相册成功。

### 3.3 比例和导出边界

界面方向和导出图片比例是两个独立选项。已有 11 比例不因重构被移除；设计中的 `3:4`、`9:16`、`16:9`、`1:1` 已有对应项，**`3:4.6` 长卡不在原比例枚举中**，须作为明确的新比例设计、校验和测试，不拿 3:4 冒名顶替。

建议先让四个代表比例完成验收，再补齐其余已有比例及长卡；发布门槛为对外提供的全部比例通过验证。显示未评与 0、12 维完整性和算法标识优先于装饰。PNG 直接使用同一人物／评分／卡片模型，不再单独构造一个只显示总分的工程图。

## 4. 关键依赖路径

**M0 素材保全与口径冻结 → M1 数据／存档契约 → M2 双算法 → M3 横竖屏编辑闭环 → M4 正式卡片／保存恢复 → M5 全量验收与候选包。**

M1 完成后可先搭 M3 的空界面，但任何正式总分必须等 M2；素材来源未核验可用占位图继续开发，不能以来源核验阻塞全部无关逻辑。发布画像需要另外通过素材门禁。

## 5. 里程碑与原子任务清单

复杂度 `[低/中/高]`，规模 S/M/L 为相对工作量而非工期承诺；`[安全]` 为数据、文件或输入校验敏感任务。每一行都有二元验收条件。

### M0：独立产品基线与素材安全 — S

交付：可追溯的素材清单、明确的规则决策；暂不改评分界面。

- [ ] M0.1 基线盘点 `[低]`：记录当前提交、工作区已有改动、入口和可用命令；完成定义：清单能区分本轮改动与既有 `design/`、下载脚本，且未改音乐兄弟仓库。
- [ ] M0.2 图片保全 `[中][安全]`：先复制画像到非构建目录并生成文件大小／SHA-256 清单；完成定义：265 个原始文件均有可校验副本，原目录未删除，执行构建前保护已证明有效。
- [ ] M0.3 素材来源盘点 `[中]`：按稳定 ID 建立人物—图片—来源记录，区分古画像、后制图、视频封面和待核验；完成定义：无“下载成功＝公有领域”的推断，未核验素材可回退占位图。
- [ ] M0.4 规格确认 `[中]`：确认 B 刻度／精度／缺项、默认算法与版本身份；完成定义：每个建议项已标明采用、修订或暂缓，没有需要实现者自行猜测的计算口径。

### M1：帝王领域、人物名录与双算法存档 — M

交付：最小人物名录可加载、空草稿可保存恢复；暂不承诺完整 UI。

- [ ] M1.1 人物元数据 `[中]`：定义稳定人物 ID、朝代、姓名／庙号／谥号／年号、在位区间数组、身份类型、资料出处、画像引用；完成定义：能表达复辟／多段在位和追尊／争议，无需用错误字符串凑唯一键。
- [ ] M1.2 评分数据判别 `[中]`：A、B 有独立版本和刻度；完成定义：B 的 `null`、0 和小数能往返且不经过旧音乐取整逻辑。
- [ ] M1.3 草稿及缓存隔离 `[中][安全]`：按人物与算法保存输入，使用帝王命名空间；完成定义：切算法、换人、刷新后数据各归其位，原 `xdrate.music.*` 字节不变。
- [ ] M1.4 导入／导出校验 `[高][安全]`：建立帝王 JSON 契约与可读错误；完成定义：非法 ID／重复维度／错误刻度／音乐或游戏档案不会被误认，错误导入不覆盖现有草稿。
- [ ] M1.5 最小资料集 `[中]`：少量经核验人物，仅填基本资料和来源；完成定义：所有初始评分为未评，没有来源文件名排名或预设评语。

### M2：双算法纯逻辑与明细 — M

交付：无界面依赖的 A／B 计算及完整测试。

- [ ] M2.1 A 保持等价 `[中]`：抽离／适配当前 LV 表、有效轴规则与固定扣分；完成定义：原有有效夹具逐项输出一致，未新增 v5 或红心行为。
- [ ] M2.2 B 固定公式 `[中]`：12 个稳定 ID 与整数百分数常量；完成定义：权重和 100%、全部基向量及 45 文档数值向量准确通过。
- [ ] M2.3 完成状态与错误 `[中]`：校验缺值、0、边界、精度、非有限值；完成定义：全 0 可计算，任一 `null` 不产正式总分，缺项不重归一化。
- [ ] M2.4 贡献与版本 `[中]`：产出明细、权重覆盖和实际算法版本；完成定义：明细原始贡献和总和一致，最终才舍入，页脚不再固定打印音乐 v4。
- [ ] M2.5 切换契约 `[中]`：连接双草稿而不是重写分值；完成定义：A→B→A 后 A 的分数、理由、权重及修改状态完全保留，取消不修改任何数据。

### M3：横竖屏帝王评分工作台 — L

交付：可以在手机与桌面完成名录选择、评分、清除和恢复的真实界面。

- [ ] M3.1 产品入口与名称 `[中]`：新入口显式加载帝王域；完成定义：正常访问不出现音乐／游戏主界面、海棠仙模板或旧路径分流。
- [ ] M3.2 宽屏三栏 `[中]`：名录／卡片／编辑器；完成定义：检索承诺的姓名、本名、庙号、谥号、年号均有匹配测试，切人物不残留上一人的标签。
- [ ] M3.3 竖屏三流程 `[高]`：真实名录、维度格和评分抽屉、生成页；完成定义：320px 宽及短视口可完成评分，假手机外框不进入应用，键盘不挡主操作。
- [ ] M3.4 双算法控件 `[中]`：固定百分比与 LV 各按真实规则显示；完成定义：B 中无禁用／删除／改百分比控件，A 中可自定义且无音乐默认轴名。
- [ ] M3.5 雷达与条形互补 `[中]`：分组数值和缺评表达；完成定义：12 个维度都有可读名称及值，`null` 和 0 在图形与读屏中都可区分。
- [ ] M3.6 理由与署名 `[低]`：维度理由、一句话评价、总体评价和个人签名档（可选）；完成定义：双向编辑／保存／预览无静默丢失，空提示不写入评分内容。
- [ ] M3.7 可读性与主题 `[中]`：宣纸主题优先，若提供深色须显式独立控制；完成定义：普通界面文字对比度目标至少 4.5:1、主体字号至少 14px，系统主题切换不造成浅字浅底，也不修改导出卡片主题。

### M4：正式卡片、PNG／JSON 与失败恢复 — L

交付：能真实生成帝王评分卡并保存，刷新／失败／取消不丢编辑。

- [ ] M4.1 帝王卡片模型 `[高]`：以真实人物和算法结果驱动，模板含身份、画像、算法、完整性、数值、评价与署名；完成定义：预览与导出都无音乐艺术家／专辑、海棠仙或工程验证图残留。

- [ ] M4.3 图片生成及下载 `[中][安全]`：沿用可验证的本地导出链路；完成定义：点击能得到可解码 PNG，渲染完成前不保存旧状态，失败不丢评分。
- [ ] M4.4 JSON 备份与恢复 `[中][安全]`：完整保存人物、两份草稿和算法版本；完成定义：导出后重新载入得到相同评分和卡片参数，截断／不兼容文件提示可理解错误且不覆盖数据。
- [ ] M4.5 分享交接 `[中]`：按运行平台实际能力提供系统分享／下载回退；完成定义：取消返回编辑，内容变更时给生成新图／取消／用旧图选择，取消在中间；没有平台能力时不伪报相册或发布成功。
- [ ] M4.6 数据保护 `[中]`：一键清空、模板替换、换人和退出均有合理保护；完成定义：确认才覆盖，取消内容不变，恢复操作不把 A 的 0 变成 B 未评或相反。

## 6. 测试矩阵与回归风险

| 类别 | 必测内容 |
| --- | --- |
| A 等价性 | 全部 LV；空轴；0 未评；禁用；固定扣分；封顶封底；旧输入不重算。 |
| B 数学 | 每维单独满分、全 0／全满／全 80／全 55.5、73.3 组合、81.8 民心增量；精度、非法数、缺项、重复 ID。 |
| 切换状态 | A↔B、同名人物、换人、取消、恢复、两份草稿均往返，模式取消不能落入旧代码的“取消也改 custom”行为。 |
| UI | 名录、搜索、抽屉、滑块／数值／±／清除此项、12 维文字表、软键盘、安全区、触控与键盘。 |
| 导出 | 每个比例、算法标识、未完成标记、中文长名／混排、一句话 24 字边界、实际 PNG 解码及尺寸。 |
| 隐私与离线 | 生产界面无第三方请求、无远程字体；画像相对路径、丢图回退、缓存拒绝／容量不足、导入校验。 |
| 素材与包 | 图片源不在 dist 唯一保存、清单哈希、来源核验、稳定 ID、来源排名不显示、发布目标不碰音乐版。 |

当前已存在的命令是 `npm run typecheck`、`npm test`、`npm run test:e2e`、`npm run build`、`npm run toy:build`、`npm run toy:audit`、`npm run minitool:build`、`npm run minitool:audit`。**M0 素材保全前不得为“验证”直接运行会清理 dist 的构建命令。**

## 7. 风险、待确认及后置项

- **M0.2 是硬前置**：素材唯一位于被忽略的构建目录，先保全，禁止直接移动、删除或运行现有下载脚本补救。
